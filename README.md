# 疾控汇总发布安全审查台

疾控数据员在公开「分区 × 年龄组」汇总检出数前，用本工具审查：**多份已公开汇总叠加后，是否会暴露小样本格（原检出数 1~4）的取值**。技术栈：FastAPI + SQLite + z3-solver。

## 快速开始

### Docker Compose（推荐）

```bash
docker compose up --build
```

访问：
- 内部审查台：http://localhost:8000/ （实例 web-a）
- 公开页：http://localhost:8000/public
- **并发导入演示页：http://localhost:8000/demo**
- 第二实例（同一 SQLite 文件）：http://localhost:8001/

`web-a` 与 `web-b` 是**两个独立的服务进程**，共享命名卷 `app_data` 中的同一个
`/data/app.db`。演示页会同时把两份 CSV 分别发给两个实例，直接展示跨进程并发行为。
重启后数据保留。

### 本地运行

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

库文件默认在 `./data/app.db`，可用环境变量 `DB_PATH` 覆盖。
要本地模拟 Compose 的双实例，另起一个进程并让二者指向同一 `DB_PATH`，同时设置
`SELF_URL` / `PEER_URLS`（见 `docker-compose.yml`），演示页即可跨进程发起并发导入。

### 自测

## 首次导入的并发语义

导入**全局只有一次**。首次导入不是「检查后插入」，而是：

1. 解析并校验整份 CSV（≤16 格、人数 ≥5、检出数 0~人数整数、组合唯一）——纯函数，不碰库。
2. 在 `BEGIN IMMEDIATE` 写事务内插入一行 `survey` 身份记录 + 全部 `cells` 行，一次 `COMMIT`。
3. SQLite 写锁在**同一文件的所有进程间**串行：先拿到锁的请求完整提交成为获胜调查；
   另一方的 `BEGIN IMMEDIATE` 会等到锁释放，随后看到已存在的 `survey` 行，
   收到 **409「调查数据已导入，不可更换」**，不写入任何格值。

因此：

- 无论两个请求来自同一进程，还是共享同一 SQLite 的两个服务进程，
  **最终只保留一份完整文件**，另一方收到冲突响应；
- 两份文件各自 9 格也不会拼成 18 格；
- 写入中途异常或进程崩溃：事务未提交，SQLite 日志回滚，**不留部分格值**，
  也不会留下半条调查记录；下次请求仍可正常首次导入；
- 预览、公开页、后续汇总发布都按获胜调查的 `survey.token` 过滤读取，
  **不会混入另一份文件的数据**（即使库中人为残留其他 token 的行）。

单份 CSV 的校验规则、公开字段（只输出人数与获准汇总，绝不输出 `detected`）和安全审查规则保持不变。

### 数据模型

| 表 | 说明 |
|---|---|
| `survey` | 全局唯一（`id=1`）的获胜调查身份：`token`、`imported_at` |
| `cells` | `(survey_token, district, age_group)` 主键；导入后不可更换 |
| `publications` | 发布汇总，带 `survey_token`，只插入不撤销 |

旧版本（无 `survey_token`）的库启动时自动迁移：原有格值与公开记录整体归入 `legacy`
调查并保留；若旧库格数超过 16（旧版并发缺陷遗留的拼接数据）会记录警告，提示人工核对。

## 演示流程（内置示例数据）

示例 A（`sample_survey.csv`，2 分区 × 2 年龄组，人数均 10）：

| 分区 | 年龄组 | 人数 | 检出数 |
|---|---|---|---|
| 城东 | 青年 | 10 | **2**（受保护小样本格） |
| 城东 | 老年 | 10 | 8 |
| 城西 | 青年 | 10 | 8 |
| 城西 | 老年 | 10 | 8 |

示例 B（`sample_survey_b.csv`）：城南/城北各 2 格，分区与 A 完全不同。

### A. 演示并发导入

1. 打开 http://localhost:8000/demo 。
2. 页面默认载入示例 A 与示例 B，点「发起并发导入」。
3. 观察：恰好一份 `201 获胜`、另一份 `409 冲突`；下方两个实例显示的
   `survey_id`、格数、分区完全一致；数据库中只有获胜文件的格值（4 格，不会拼成 8 格）。
4. 点「清空数据（仅演示模式）」可重复演示。`DEMO_MODE=1` 时才开放重置接口，
   普通部署不设置该变量即无法重置。

### B. 演示安全审查

1. 打开内部台 `/`，点「导入示例数据」（导入后不可更换）。
2. 勾选「城东」+ 两个年龄组 → 预览（总数 10，安全）→ 确认发布。
3. 勾选两个分区 +「老年」→ 预览（总数 16）：单独看本安全，但与已发布的「城东」合并后，
   格「城东/青年」被约束到 **[0, 4]**（`城东合计10 − 城东老年≤10 ⇒ 城东青年≤4`，
   且 `老年合计16 ⇒ 城东老年≥6 ⇒ 城东青年≤4`），不再保留「≥5」的可行解 → 审查不通过。
4. 点「确认发布」→ 在跨进程写锁内按最新公开记录重核，返回 409 并列出受影响格与可行范围。
5. 改发「青年」（总数 10）：与已公开记录合并仍安全 → 发布成功。
6. 打开公开页 `/public`：只有人数表与获准汇总，无格内检出数。

## 安全模型

- 未知量：每格一个整数 `x_i`，约束**仅**来自
  1. 界限 `0 ≤ x_i ≤ 人数_i`；
  2. 历次公开记录：所选交集格之和 = 公开总数；
  3. 候选发布：所选交集格之和 = 候选总数。
- 判定：对每个原检出数为 1~4 的格，须同时存在 `x_i = 0` 与 `x_i ≥ 5` 的可行整数解，
  否则拒绝并给出该格可行范围（z3 Optimize 求 min/max）。
- 确认发布时在 `BEGIN IMMEDIATE` 写锁内**重读最新公开记录并重核**，随后同事务写入：
  两个各自安全、合并不安全的窗口不会都被发布；保存失败整体回滚，不留半次发布。
  写锁若发现公开记录已在别处变化，会按新快照重新评估后重试，不用过期结论放行。
- 求解在工作线程执行（每评估独立 z3 Context，线程安全），求解期间公开页与其他请求可用。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/import` | 导入调查 CSV（全局仅一次；并发落败方 409） |
| GET | `/api/admin/state` | 内部状态（含格内检出数、获胜 survey_id） |
| POST | `/api/preview` | `{districts, age_groups}` → 交集总数 + 安全评估（仅获胜调查） |
| POST | `/api/publish` | 跨进程写锁内重核后发布；不安全返回 409 + 受影响格与可行范围 |
| GET | `/api/public` | 公开数据：仅人数与获准汇总 |
| GET | `/api/demo/config` | 演示配置（本实例与对端地址） |
| POST | `/api/demo/import-pair` | 向两个实例并发导入 `file_a` / `file_b`，返回双方响应与一致状态 |
| POST | `/api/demo/reset` | 仅 `DEMO_MODE=1` 可用：清空调查与发布 |

CSV 表头：`分区,年龄组,人数,检出数`（亦兼容 `district,age_group,population,detected`）。
校验：≤16 格；人数 ≥5；检出数为 0~人数整数；（分区,年龄组）唯一。

## 已知限制

- 未实现认证/授权：内部台与接口对任何可达者开放，生产部署须自行加访问控制。
  尤其 `DEMO_MODE=1` 会开放重置接口，仅用于演示。
- 并发正确性依赖 SQLite 的单写者模型与共享文件系统；把 `DB_PATH` 指向网络文件系统
  （某些 NFS 配置）会削弱 SQLite 文件锁语义，生产应使用本地卷或换成服务端数据库。
- 审查基于精确整数可行域（z3），非差分隐私；它保证「小样本格不被公开信息钉死」，
  不量化其他泄露渠道。
- 旧库迁移只能整体归入 `legacy`，无法自动拆分旧版并发缺陷已拼接的两份文件；
  如遇格数超限会告警，需人工核对。
